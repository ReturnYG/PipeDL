# 设计与性能改造

原来的卡顿不能仅归因于 Python。原实现把部分进程控制放在界面操作路径中，界面定时重查数据库、重建实验卡片，调度与刷新依赖轮询。换语言而保留这些调用方式，仍然会有延迟。

新版本采用 Tauri 2 + Rust + React/TypeScript。Tauri 使用系统 WebView：Windows 为 WebView2，Linux 为 WebKitGTK。界面、HTTP 服务、SQLite/进程调度各自分工，耗时操作不在界面线程中执行。

```text
桌面 Web UI / 外部脚本
          │ HTTP + Bearer token
          ▼
     Axum 本地 API ── SSE 状态通知 ──► Web UI
          │ 消息队列
          ▼
     单一调度线程
       ├─ SQLite：配置、顺序、实验状态与历史
       ├─ Windows Job Object / POSIX 进程组
       └─ stdout / stderr 日志文件
```

唯一的实验控制入口是 HTTP API。Tauri IPC 只用于提供本地连接凭据、退出应用和打开官方更新页面。Bash、PowerShell、CMD、WSL 是实验的运行环境，不是重复的控制入口，因此仍予保留。

核心行为包括：串行执行、暂停/恢复整个队列、暂停/恢复当前实验、停止、取消排队、重新排序、重试、删除、历史记录和日志查看。每个控制请求都核对实验 ID；停止先返回接受状态，后台处理进程结束。Web UI 通过事件刷新状态，日志按字节游标增量读取，只显示有界长度，避免不断读取整个日志文件。

数据库与进程由一个线程独占，避免多个调度器争抢同一实验。运行中的任务每 100 ms 检查结束状态，空闲时等待消息。启动前获取数据目录锁；旧版本数据库先备份，异常退出遗留的任务进入待确认状态，不直接向旧 PID 发信号。关闭窗口隐藏到托盘，主动退出时拒绝中断正在运行的任务。

维护入口见 [development.md](development.md)，迁移与回滚见 [migration.md](migration.md)。测试和发布流水线已纳入仓库；持续维护仍需在后续版本中运行这些检查、审查依赖和发布签名。当前更新按钮打开官方发布页，自动更新需要先建立签名发布渠道。
